EXPERIMENT 9 - JENKINS PIPELINE SCRIPT AND BUILD TRIGGERS
============================================================
SUB-EXERCISE 1 - CREATE SCRIPTED/DECLARATIVE PIPELINE
1. Jenkins -> New Item -> enter pipeline name -> Pipeline -> OK.
2. Configure -> Pipeline -> Definition: Pipeline script.
3. Paste and edit the pipeline below. Set Maven tool name exactly as configured in Jenkins Global Tool Configuration.

pipeline {
    agent any
    tools {
        maven 'MAVEN-HOME'
    }
    stages {
        stage('Checkout') {
            steps {
                git url: 'https://github.com/username/repository.git', branch: 'main'
            }
        }
        stage('Clean') {
            steps {
                bat 'mvn clean'
            }
        }
        stage('Compile') {
            steps {
                bat 'mvn compile'
            }
        }
        stage('Test') {
            steps {
                bat 'mvn test'
            }
        }
        stage('Package') {
            steps {
                bat 'mvn package'
            }
        }
    }
}

For Linux Jenkins replace bat with sh, for example sh 'mvn clean'.
Save -> Build Now -> Console Output.

SUB-EXERCISE 2 - BUILD TRIGGERS
1. Open job -> Configure -> Build Triggers.
2. Choose required trigger:
GitHub hook trigger for GITScm polling.
Poll SCM schedule: H/5 * * * *
Build periodically at 6 PM: 0 18 * * *
3. Save.

SUB-EXERCISE 3 - PIPELINE SCENARIO CHANGES
Clean workspace stage:
stage('Clean Workspace') { steps { deleteDir() } }
Compile Java file:
stage('Compile') { steps { bat 'javac Hello.java' } }
Run tests:
stage('Test') { steps { bat 'mvn test' } }
Package project:
stage('Package') { steps { bat 'mvn package' } }
Print build number:
echo "Build Number: ${BUILD_NUMBER}"
Add deployment as a Deploy stage after Package.
Use checkout stage before build to get latest GitHub code.
Use Jenkins Credentials Manager for private repository credentials; never hardcode tokens.
Use tools { maven 'MAVEN-HOME' } with the exact configured Maven tool name.
If clone fails, checkout stage fails and later stages stop.
If test/install fails, pipeline normally stops at failed stage.
If project directory changes, update every Maven command's -f path.
